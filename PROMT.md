# AnyPS5 — AGC SHADER HEADER COMPATIBILITY: COMPLETE FIX

## Цель

Исправить аварийное завершение игры:

```text
AGC driver: rectangle ABI refers to a replaced shader header
(user-data presence differs; code=0x78dec00 registered=0x78df5e0 actual=0x78df900)
FATAL: abort() (SIGABRT)
exit 0xC0000409
```

Работай в существующем репозитории AnyPS5. Найди первопричину, исправь её, собери Windows-версию, запусти регрессионные тесты и повторно проверь игру.

Не переписывай графический backend целиком. Не отключай проверки ABI. Не подавляй исключения. Не объявляй успех без реального подтверждения.

## 5. Исправь сценарий A: отличающийся user_data

Проверь, присутствует ли исправление #1837.

Если отсутствует, перенеси его решение в текущую ветку.

Если присутствует, проверь, почему rectangle ABI по-прежнему выдаёт `user-data presence differs`.

## 6. Исправь сценарий B: перемещённая копия header

Исследуй изменение `SameHeader`, описанное в обсуждении #2884.

При копировании структуры на другой адрес внутренние указатели могут продолжать ссылаться на массивы исходного объекта. Поэтому обычное сравнение адресов указателей может ошибочно объявить корректную копию несовместимой.

Проверь для каждого соответствующего поля:

- указывают ли исходный и скопированный заголовки на одинаковое содержимое;
- находится ли объект в ожидаемой области памяти;
- совпадают ли внутренние данные;
- являются ли указатели абсолютными, относительными или частью другой модели адресации;
- корректно ли учитывается размер и время жизни данных.

Не предполагай, что все указатели обязаны быть равны или что все они должны смещаться одинаково.

Если подтверждено, что поля указывают на соответствующие области одной логической структуры, сравнивай их по корректному отношению эквивалентности, определённому фактическим контрактом.

Если копия действительно содержит неправильные указатели, не принимай её как допустимую.

## 7. Исправь сценарий C: разные заголовки с общим shader code

Исследуй случай из issue #2856.

Несколько заголовков могут использовать один shader code, но иметь разные ABI metadata или указатели на регистры и семантики.

Проверь, не использует ли реестр адрес shader code как единственный идентификатор объекта.

Установи:

- могут ли несколько зарегистрированных header легально ссылаться на один code;
- как выбирается зарегистрированный header;
- какие metadata принадлежат каждому header;
- как выбирается snapshot;
- когда предыдущая регистрация становится неактуальной;
- как различаются идентичность кода и идентичность ABI.

Если общий code допустим, не объединяй автоматически разные ABI в один объект.

Сохраняй правильную регистрацию и выбор соответствующих metadata.

## 10. Раздели четыре понятия

Не смешивай:

1. Идентичность объекта.
2. Эквивалентность содержимого shader header.
3. Совместимость ABI.
4. Действительность времени жизни объекта.

Исправление должно сохранять различие между этими понятиями.

Если два объекта эквивалентны по содержимому, но имеют разные адреса, это не обязательно ошибка.

Если два объекта используют один shader code, это не означает, что они имеют одинаковый ABI.

Если два объекта совместимы по ABI, это не разрешает использовать освобождённую память.

Если header заменён, это не означает автоматически, что старый неизменяемый snapshot недопустим для уже созданного потребителя.
